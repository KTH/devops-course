## Description
We will demonstrate our implementation of CI and testing tools on a previous school project. The project is a quiz website (specifically for anime) built on nodeJS using JavaScript. Our unit tests will be done through vitest, while our E2E testing will be done with playwright. To automate the continuous integration, we will use Github action to build and test new code for every push or pull request. Testing will be done live, including dynamically modifying code, seeing how builds of the website are effected and how our tests will react to them. 

The demonstration will have a bit of theory, how software testing is divided in 3 sections (unit, integration and E2E testing) explaining the importance of testing, specifically E2E testing. Discussion will also be focused on what E2E tools can do. as it covers the experience/workflow of the user, which is especially important for websites designed for laypeople. We will also discuss weaknesses of our approach.

**Relevance**
By adding continuous integration in a project, developers become more independent and efficient, removing overhead from communication with development teams. Through our demonstration we show interesting and efficient ways to test software. Furthermore, we will talk and showcase cool ways of doing E2E testing, which is important as user experience can sometimes be forgotten in the process of development.
